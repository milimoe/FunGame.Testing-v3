# 可视化决策表编辑器

入口位于 webui 首页工具菜单和侧栏的最后一项“决策表编辑器”，直接路径为 `/decisiontable`。页面编写 Core 协议版本 1 的 `beforeDecision` 配置，导出后由宿主加载并绑定角色；不会自动修改运行中的对局。

## 编辑

- 设置策略 ID（`module:name`）及未命中时的 `defaultAI` / `endTurn` 回退。
- 添加、复制、删除、启停规则，设置优先级，使用箭头调整配置顺序。高优先级先匹配，同级按配置顺序；右侧展示启用规则的实际匹配顺序。
- 目标支持自身、友方（含自身）和敌方，以及生命比例、距离排序。目标绑定和方案绑定可被条件与动作引用；改名会同步当前规则中的内置引用，目标与方案同名时各自独立。
- 动作支持普攻、技能、物品、接近、撤离和结束回合，以及移动策略、位置偏好和风险上限。协同仍受 Core 的原地限制。
- 条件支持全部内置叶节点及嵌套 AND / OR / NOT。根节点深度为 0，最多嵌套 16 级，每个组合最多 64 个直接子条件；最多 256 条规则。
- 技能和物品目录来自 `/api/gamedata`，按名称或 ID 搜索；离线时可手动输入 ID。治疗模板使用实际模组的回复弹，空表和攻击模板不依赖目录。
- 自定义条件、动作的标识和 JSON 参数可编辑；使用配置的宿主需注册对应扩展。当前 WebAPI 的 Core 校验仅识别其实际注册的内容。

有效草稿自动保存在当前站点的浏览器本机存储，刷新可恢复。配置错误或参数 JSON 无效时保留上一份有效草稿，不覆盖它。撤销、重做最多保留 50 次编辑历史，刷新后重新开始记录；模板载入和导入替换也可撤销。

JSON 可粘贴或选择文件导入；失败时保留当前配置。支持实时 JSON 预览、复制和下载。未知字段、无效绑定及配置边界会显示定位诊断。浏览器无法精确表示的大整数和溢出数值会被拒绝导入，避免静默更改 ID 或参数。

## Core 校验接口

`POST /api/decision-tables/validate` 接收：

```json
{
  "json": "{\"id\":\"example:empty\",\"rules\":[]}",
  "checkResources": true
}
```

调用 Core Parser、Compiler.Validate 和 Compile，返回 `valid` 与 `diagnostics`（`path`、`message`、`code`）。开启资源检查时验证当前模组技能和物品 ID；关闭后保留 Core 结构、绑定及扩展检查。该接口只校验，不注册策略、不绑定角色、不保存服务端文件。

本地结构检查和 Core 编译检查分别展示；配置或校验选项修改后，已有 Core 结果标记为过期。服务端不可达时保留本地编辑与导出能力。下载不代表已经完成 Core 校验，也不代表技能在任意角色、局面或协同中可执行。

## 开发验证

在 `webui/` 运行：

```powershell
npm run build
npm run test:decisiontable
```

默认执行本地协议回归，跳过需要服务端的 HTTP 集成。启动包含本接口的 WebAPI 后，可同时验证真实 Core 编译及模组目录：

```powershell
$env:DECISION_TABLE_API = 'http://127.0.0.1:11030'
npm run test:decisiontable
```

测试涵盖 Core 默认字段、显式 null、规则与条件数量、语义和 JSON 深度、绑定、扩展参数、数值精度、模板配置及 HTTP 编译。浏览器验收需检查首页入口顺序、规则增删复制排序、条件编辑、导入失败保护、JSON 下载、撤销重做、刷新恢复及窄屏布局。
